# Ebonkeep Project Guidelines

## Always Update Documentation
When making changes, ALWAYS update these files:
1. **README.md** - Main project overview and setup
2. **CHANGELOG.md** - Log all feature additions and breaking changes
3. **Module-specific READMEs** - Update if adding/changing modules
4. **Setup guides** - Update if changing configuration requirements

## Critical Rules

### Database Changes
- After modifying `apps/api/prisma/schema.prisma`:
  1. Run `cd apps/api && npx prisma generate` to regenerate client
  2. Run `cd apps/api && npx prisma migrate dev --name <description>` for migrations
  3. Update relevant .md documentation
  4. Test that the API builds successfully

### New Features
- Create feature-specific setup guides (e.g., `PAYPAL_SETUP.md`)
- Update main `README.md` with overview
- Add to `CHANGELOG.md`
- Include database schema changes if any
- Document all environment variables in `.env.example`

### API Modules
- Location: `apps/api/src/modules/<module-name>/`
- Always register new routes in `apps/api/src/index.ts`
- Use `{ preHandler: fastify.authenticate }` for protected endpoints
- Access user via `request.user.accountId` and `request.user.playerId`

### Frontend Components
- Location: `apps/web/src/components/`
- Import in `App.tsx` if needed in main app
- **CRITICAL: Always use i18n for all user-facing text**
  - Import: `import { useTranslation } from "react-i18next";`
  - Hook: `const { t } = useTranslation("common");`
  - Usage: `{t("section.key")}` instead of hardcoded strings
  - Add ALL new strings to `apps/web/src/i18n/locales/en/common.json`
  - Never use hardcoded English text in JSX/TSX components
  - This includes: buttons, labels, titles, descriptions, error messages, success messages
- Update navigation if adding new tabs/pages

## Internationalization (i18n) Rules

**MANDATORY for all UI text:**
1. **Never hardcode user-facing text** - Always use `t()` function
2. **Add translations to ALL locales immediately** - When creating new UI text:
   - Add to English: `apps/web/src/i18n/locales/en/common.json`
   - **CRITICAL**: Add translations to ALL other locale files simultaneously:
     - `zh-CN/common.json` (Simplified Chinese)
     - `es-419/common.json` (Latin American Spanish)
     - `pt-BR/common.json` (Brazilian Portuguese)
     - `ru/common.json` (Russian)
     - `fil/common.json` (Filipino)
     - `ko/common.json` (Korean)
   - Users will see English fallback text if translations are missing!
3. **Organize by section** - Group related translations (e.g., `shop.*`, `settings.*`, `errors.*`)
4. **Use interpolation** - For dynamic values: `t("key", { value: variable })`
5. **Check existing keys** - Reuse existing translations when applicable (e.g., `currencies.imperials`, `app.errorPrefix`)

**Translation key structure:**
```json
{
  "section": {
    "subsection": "Text",
    "withVariable": "Text with {{variable}}",
    "nested": {
      "key": "Value"
    }
  }
}
```

**Example - Bad (hardcoded):**
```tsx
<h2>Imperial Shop</h2>
<button>Buy Now</button>
```

**Example - Good (i18n):**
```tsx
const { t } = useTranslation("common");
<h2>{t("shop.title")}</h2>
<button>{t("shop.buyNow")}</button>
```

**When adding new features:**
- [ ] Add all text to i18n file first
- [ ] Use `t()` for all user-facing content
- [ ] Test language switching works
- [ ] Document new translation keys in PR/commit

### Shared Types
- Location: `packages/shared/src/index.ts`
- Always export both schema (Zod) and type (TypeScript)
- Rebuild after changes: `npm --workspace @ebonkeep/shared run build`

### Transaction/Payment Code
- Keep in `/transactions` folder for platform independence
- Follow adapter pattern for multi-platform support
- Document payment flow in relevant .md files
- Never commit real credentials

### Environment Variables
- Add ALL new env vars to `.env.example` with comments
- Document purpose and format clearly
- Note which vars are required vs optional
- Provide sandbox/test defaults when applicable

## Project Structure Reference
```
├── apps/
│   ├── api/          # Fastify backend
│   │   ├── src/modules/   # Feature modules (auth, payments, etc.)
│   │   └── prisma/        # Database schema & migrations
│   ├── web/          # React frontend
│   └── desktop/      # Electron wrapper
├── packages/
│   └── shared/       # Shared types & contracts
├── transactions/     # Payment adapters (PayPal, Steam, etc.)
├── docs/            # Design & architecture docs
└── tools/           # Code generation scripts
```

## Before Committing
- [ ] Run `npm run build` from root
- [ ] Check for TypeScript errors
- [ ] **Verify all UI text uses i18n** - No hardcoded strings
- [ ] **Verify translations in ALL 7 locales** - Check en, zh-CN, es-419, pt-BR, ru, fil, ko
- [ ] **Test language switching** - Change language in Settings, verify new text appears translated (not English fallback)
- [ ] Update README.md if adding features
- [ ] Update CHANGELOG.md
- [ ] Add/update setup guides for new integrations
- [ ] Update .env.example with new variables
- [ ] Test locally with `run-local.bat`

## Common Issues

**Prisma errors after schema changes:**
```bash
cd apps/api
npx prisma generate
npx prisma migrate dev
```

**TypeScript path errors:**
- Check `tsconfig.json` paths configuration
- Ensure module is built: `npm run build`

**Module import errors:**
- Use `.js` extensions in imports for ESM compatibility
- Rebuild packages after shared type changes
